После исправлений полный прогон 69 сценариев повторён успешно. Скриншоты мобильного результата и ранее проверенная композиция сохраняют выбранный дизайн.

```sh
npm test
VITE_BASE_PATH=/ npm run build
npm run test:e2e
npm run test:lighthouse
npm run test:local
node scripts/measure-bundle.mjs --out docs/collision-bundle.json
git diff --check
```

Playwright покрывает 360/767/768/1280 CSS px, длинные названия и URL, reduced motion, 200% zoom-equivalent reflow, цель 44px, axe, cancel/resume/late worker messages, найденные и ненайденные маршруты, mobile/desktop offline и восстановление после render error. E2E использует настоящий worker/BFS с mocked API; контролируемые worker-сообщения применяются только для lifecycle/budget/malformed-route сценариев.

Проверка локального режима использует fixture-граф из шести статей, а не полный дамп. Она проверяет кратчайший путь, одну загрузку графа на worker и ноль запросов к Википедии. Тестовый `public/graphs/en.bin.gz` удаляется после проверки.

Снимки idle/searching/found/notFound на 360 и 1280 доступны в `test-results/` и приложениях отчёта Playwright. Концепты и условные цепочки в них не подтверждают существование связей в актуальной Википедии; фактические маршруты продукта формируются из результата поиска. Live API performance этим аудитом не измеряется. Lighthouse оценивает начальное состояние production-сборки, три mobile запуска с медианой и прежними порогами.

Размер JS/CSS/worker/шрифтов записывается в [collision-bundle.json](collision-bundle.json); изображения учитываются отдельно в [image-sizes.json](image-sizes.json). Генерация, prompts и источники лицензий описаны в [collision-assets.md](collision-assets.md).
