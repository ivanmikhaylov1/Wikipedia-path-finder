# «Несовместимые страницы»: дизайн «Переходов»

Дата: 2026-10-03. Ветка: `redesign/incompatible-pages`, создана от `origin/main` (`01e1814`). Статус: конкретная спецификация для пользовательского review; реализация ещё не начата.

## Намерение и критерий успеха

Пользователь хочет максимально смелый арт-объект и разрешает отойти от привычного построения интерфейсов. Успех — запоминающаяся разорванная энциклопедия, внутри которой можно выбрать две статьи, наблюдать реальный поиск связи и открыть статьи найденного маршрута. Выбор темы, отдельный выбор языкового раздела и переключатель межъязыкового режима исчезают.

Одобрена концепция столкновения энциклопедий. Данная спецификация фиксирует её поведение для review перед планом реализации. Она не утверждает, что любой маршрут существует или найденный маршрут глобально кратчайший.

## Визуальная система

Вся поверхность — один разорванный печатный разворот. Бумажно-белая основа `#f4f1e8`, почти чёрный текст `#11110f`, электрический синий `#123bff`. Одна постоянная палитра, без выбора темы. Контраст проверяется для каждого текста и состояния, а оттенки уточняются при необходимости ради читаемости.

Левый фрагмент — выразительная антиква с поддержкой кириллицы; правый — плотный гротеск. Для основной читаемой информации используются локальные шрифты проекта; лицензии дополнительных локальных гарнитур сохраняются, если потребуется новая антиква. Маленькие номера, подписи разделов и тонкие линейки создают энциклопедическую структуру. Цвета не несут смысл без подписей.

Основной жест — разорванный центральный шов и несовпадение печатных сеток. Крупные названия, иллюстрации и намеренные обрезки декоративных повторов создают напряжение. Основное название выбранной статьи всегда доступно полностью: длинные названия уменьшаются и переносятся. Декоративная типографика не попадает в accessibility tree.

Концепт-эскиз: `docs/concepts/incompatible-pages-desktop.png`. Это визуальная референция, а не готовая страница и не источник фактов. Нарисованные в нём описания статей не переносятся в продукт.

## Первый экран и выбор статей

Первый экран содержит маленькую издательскую отметку «Переходы», два фрагмента с подписями «01 / Откуда» и «02 / Куда», огромные редактируемые названия, языковые метки и центральное действие «Столкнуть». Подпись действия: «Найдём путь по ссылкам Википедии». Иконка обмена направлениями доступна рядом с швом и имеет текстовое доступное имя.

При первом открытии показана явно обозначенная примерная пара: «Осьминоги · RU» и «Bauhaus · EN». Это статьи для запуска, не пример заранее доказанного маршрута. Названия разрешаются через API при запуске. Существующий URL запроса имеет приоритет над примером; автоматического запуска нет.

Названия — семантические редактируемые controls. На широком экране текст может выглядеть монументально, но при фокусе становится удобной поверхностью ввода. Placeholder, label, focus-ring и клавиатурное управление явны. Подсказки располагаются поверх иллюстративных областей на непрозрачной бумажной поверхности.

API-режим предлагает варианты из существующих поддерживаемых разделов RU, EN, DE, FR, ES; приоритет выдачи RU/EN соответствует русскому интерфейсу и типичной межъязыковой паре. Запросы последовательны в отдельной очереди с concurrency 1; каждая выдача объединяет до двух результатов на раздел, дедуплицирует по паре `lang/title`, показывает до восьми результатов и игнорирует устаревшие ответы. Debounce около 300 мс. Сбой отдельного раздела не скрывает результаты остальных; полный сбой получает сообщение у поля.

Каждая подсказка содержит название и раздел. Выбор сохраняет `{title, lang}`. Изменение текста сбрасывает прежний выбор. Ссылка Википедии однозначно задаёт раздел через существующий parser. Свободный текст без выбора подсказки разрешается в RU по умолчанию; его метка отображается до запуска, чтобы раздел не был скрытым предположением. Алфавит не является доказательством языка. Язык произвольного корректного URL поддерживается независимо от списка разделов подсказок.

Если разделы конечных статей различаются, межъязыковой поиск включается автоматически. При одинаковых разделах выполняется обычный поиск. Существующее ограничение межъязыкового алгоритма двумя конечными разделами сохраняется; интерфейс не обещает обход всех языков Википедии.

Локальный режим сохраняется как одноязычный: используется раздел графа из shared query или RU по умолчанию; другие разделы не запрашиваются и смешанная пара получает понятную ошибку у поля. Это ограничение появляется по контексту, без общего переключателя режима.

## Изображения

Для начальной примерной пары допустимы AI-generated чёрная гравюра осьминога и абстрактная синяя геометрическая композиция. Они явно декоративны, не считаются изображениями из статей Википедии и не приписываются Bauhaus как историческое произведение. Употребление внутри интерфейса не требует описаний статьи, полученных от модели.

Ассеты генерируются отдельными изображениями без встроенных интерфейсных надписей, сохраняются в `public/images/collision/`, оптимизируются и документируются с prompt и происхождением. Центральный шов и простая геометрия выполняются средствами CSS/SVG. Изначальный иллюстративный набор после изменения пары отступает в абстрактную печатную фактуру, чтобы не выдавать изображение осьминога за иллюстрацию новой статьи. Новые изображения во время поиска не генерируются.

## Состояния поиска

`idle`: два раздельных фрагмента и центральное действие. Постоянного движения нет.

`searching`: фрагменты смещаются навстречу. В шве появляются фрагменты названий из реальных `sampleTitles`, а не выдуманный маршрут. Показываются реальные `visited` и `depth`; при отсутствии samples работает только абстрактная фактура. Из одинаковых имён не выводится доказательство ребра между статьями. Действие заменяется на «Остановить». Ввод заблокирован на время поиска, а остановка остаётся доступной.

`found`: найденная последовательность перестраивает разворот в непрерывную бумажную полосу с последовательной нумерацией, названиями статей и прямыми ссылками. На широком экране полоса может складываться в зигзаг внутри ширины страницы; на телефоне — вертикально. Визуальный маршрут и доступный упорядоченный список — одна семантическая структура, не две конфликтующие копии. Переход между языками подписан и отличается видом соединения. Количество шагов равно количеству соединений. Никакого требования горизонтального drag для доступа к статье.

`notFound`: остаётся открытый разрыв, сообщение «Путь не найден в пределах поиска», число проверенных статей, глубина и конкретная причина остановки. При доступном resume — «Искать дальше»; иначе — «Изменить статьи». Обмен направлениями доступен как отдельное осмысленное действие. Исчерпание лимитов не объявляется доказательством отсутствия пути.

`error`: описание ошибки рядом с соответствующим полем либо в центральном шве для ошибки worker/API. Значения сохраняются, доступен повторный запуск. `cancelled`: поиск действительно прекращается, остаются выбранные статьи и сообщение «Поиск остановлен».

Ветка от main не включает предварительный маршрут по первым ссылкам из `feat/first-link-preview-2`. Он не добавляется в рамках этого редизайна.

## Движение и адаптация

Столкновение — короткий переход около 600–900 мс, а завершение — около 700 мс без искусственного ожидания результата. Реальный результат доступен сразу после получения worker message; анимация не задерживает доступность ссылок. По завершении все loops останавливаются. Главный текст не мигает и не дрожит, стробирования нет.

При `prefers-reduced-motion` итоговое состояние показывается сразу с минимальными сменами opacity. Статистика сообщается через ограниченный `aria-live`, без озвучивания каждого декоративного фрагмента.

На 360–767 px разворот вертикальный: начальная статья сверху, поперечный шов с действием в центре, конечная ниже. Названия адаптируются к длине, controls доступны без overflow. На 768 px и шире — разворот с центральным вертикальным швом. Zoom 200%, длинные кириллические/латинские названия и touch targets от 44 px входят в требования.

## Компоненты и данные

`App` продолжает владеть worker lifecycle, selected query, progress, result, notFound и resume. Интерфейсы BFS/LinkSource, search budgets, API retries и worker messages сохраняются.

Новый shell разворота заменяет старую последовательность Header/Hero/PathVisualizer/ProgressIndicator. `CollisionSpread` владеет только композицией и visual state; `ArticleField` — вводом, выбором `{title,lang}` и валидацией; `ArticleSuggestions` либо отдельный hook — объединённой выдачей с отсечением устаревших ответов; `CollisionStage` — швом и фрагментами progress; `RouteRibbon` — единственным семантическим маршрутом; `SearchStatus` — статистикой и действиями остановки/продолжения. Границы не требуют новой библиотеки или backend.

Parser и shared-query helpers переиспользуются. Старые query URL с `lang`, `from`, `to`, `mode` продолжают открываться, но фактический режим определяется конечными выбранными статьями. Кнопка «Поделиться» появляется возле готового результата, копирует URL пары и сообщает статус копирования. Она не обещает сохранение готового результата без повторного поиска.

Ссылки Википедии формируются существующим безопасным форматированием и учитывают код раздела каждой статьи. В API-режиме межъязыковые nodes декодируются существующим `articleFromKey`. Декоративный слой не получает права управлять поиском.

## Проверка перед готовностью

Unit/component tests проверяют сохранение языка выбранной статьи, сброс выбора при редактировании, автоматический межъязыковой режим, URL-определение раздела, старые shared links, stale suggestions, partial API failure, local restrictions и правильные route links.

E2E с настоящим worker и mocked API покрывают одну одноязычную и одну межъязыковую найденную цепочку, no-result и resume, API error, cancel, клавиатурный выбор подсказок и reduced motion. Старые тесты, привязанные к theme/language controls, заменяются проверками нового поведения; алгоритмические тесты сохраняются.

Запускаются `npm test`, `npm run build`, подходящие e2e и существующая проверка локального режима. Визуальный review выполняется одним батчем desktop/mobile (1280/360) для idle, searching, found и notFound, с одним исправлением выявленных дефектов и подтверждением. Axe и mechanical detector проверяют новый UI. Отдельно проверяются переполнение длинных названий, zoom и остановка анимации. Генерируемые ассеты оптимизируются и итоговый bundle измеряется; пользовательский изменённый `docs/bundle-final.json` не перезаписывается.
